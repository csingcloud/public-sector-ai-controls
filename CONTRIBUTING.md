# Contributing

Keep examples synthetic and small enough to inspect. Include the purpose,
inputs, expected output, limitations, and source references for a change.
Run the validation commands in the README before proposing a change.

Do not submit tenant exports, credentials, customer or employer data,
proprietary implementation details, or real identity/device inventories.
Framework mappings must state their version, rationale, and review status.
A relationship between controls is not proof of equivalence or compliance.

## Developer Certificate of Origin

Contributions are accepted under the
[Developer Certificate of Origin 1.1](https://developercertificate.org/).
Every commit must carry a sign-off line certifying that you wrote the change,
or otherwise have the right to submit it under this project's license:

    Signed-off-by: Your Name <you@example.com>

`git commit -s` adds the line for you. Pull requests containing unsigned
commits will not be merged. Use your real name; anonymous sign-offs are not
accepted.
